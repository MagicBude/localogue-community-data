# Pilot A 验证报告

## 1. 本批次要验证什么

Pilot A 的目标不是追求数量，而是验证一条最小但完整的数据链：

```text
Person → Work → Maker
   ↘ Source Record
   ↘ active Registry Entry
```

因此本批次只录入 3 位人物、5 部作品和引用所需的 3 个 Maker。Maker 虽不计入“3 人物 + 5 作品”的核心数量，但 Work 的 `makerId` 不能指向仓库外的悬空 ID，所以必须作为支撑实体同时发布。

## 3. 来源策略

### 3.1 直接官方来源

- 石川澪：官方 Fan Club 人物资料页、MOODYZ 官方人物页和两张官方作品页。
- 河北彩花：T-POWERS 官方事务所页、S1 官方人物页和官方作品页。
- MOODYZ 与 S1：由其官方页面页脚与作品信息支持 Maker 名称。

### 3.2 IdeaPocket 访问例外

IdeaPocket 官方人物页仍可由公开目录定位，但本次自动读取发生超时。为了不违反“不要把搜索摘要当最终来源”和“不要虚构 accessedAt”的规则，本批次没有把未成功读取的官方页写成已核验来源，而是：

1. 使用日文 `アイデアポケット` 公开目录页核对品番、完整日文原题、出演者与 Maker；
2. 使用日文 `桃乃木かな` 页面交叉核对两部作品的发行日；
3. 在每个 Source Record 中如实标记为 `database`，不标记为 `official`；
4. 待官方页恢复可访问后，再以 patch 版本增加官方来源，不重建实体 ID。

这正是稳定 ID 的价值：来源可以升级，实体身份不需要随来源变化而改变。

## 4. 有意留空的字段

- 没有中文或英文作品标题：当前没有经过核验的一致本地化映射。
- 没有简介：不复制片商或第三方长篇宣传文案。
- 没有 Label、Series、Genre：来源不明确或本批次不需要验证时，省略关系比猜测更安全。
- 没有头像、封面、剧照与任何 `assetId`。
- 没有 MediaFile、本地路径、用户 Tag、观看记录、评分或 Presentation Preference。
- 桃乃木かな的退休事件只记录到 `2025` 年：公开材料对“公告日、作品发表日、作品发行日、正式引退日”的表达并不完全等价，因此不制造虚假的日级精度。

## 5. 仓库侧验收

本批次完成后必须满足：

- `pnpm check` 通过；
- `pnpm stats` 显示 3 Person、5 Work、3 Organization；
- 11 个正式实体都有同名 Source Record；
- 11 个 ID 都以 `firstPublishedIn: 0.2.1` 登记为 active；
- 5 个 Work 的 Person 与 Maker 引用全部可解析；
- 正式数据中私人字段和图片引用数量为零。

## 6. 仍需人工完成的 Localogue 验收

仓库 Validator 能证明结构与引用闭合，但不能替代应用界面中的真实挂载。合并 Pilot B 前，应在 Localogue 中完成：

1. 将仓库根目录添加为 Shared Pack；
2. 确认 3 位人物与 5 部作品可以被读取；
3. 确认作品可以解析对应人物与 Maker；
4. 在 Private Library 对同一实体设置本地覆盖，确认 Private Library 优先；
5. 删除本地覆盖后，确认 Shared Base 重新显示；
6. 确认 Community Data 不写回任何私人状态。

把这一步保留为人工验收，是因为“JSON 合法”和“用户实际看到正确结果”是两个不同层次的质量保证。
